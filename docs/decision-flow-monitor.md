# فلوچارت زندهٔ تصمیم‌گیری رامون

صفحهٔ فارسی در `http://127.0.0.1:8013` مسیر داده، پیش‌بینی، تأییدها، تصمیم عادی/رنج، قفل‌های اکسپرت، سفارش و مدیریت پوزیشن را نشان می‌دهد. الگوی آن از `frontend/src/SystemMap.tsx` و قرارداد تازگی/منبع دادهٔ پروژهٔ `steelmaking-level2-platform` گرفته شده است.

## اجرا

از پوشهٔ پروژه:

```bash
./scripts/monitor_ramon.sh
```

بدون نیاز به ساخت دوبارهٔ مدل، نصب وابستگی جدید، درخواست `/decision` یا تغییر ورودی‌های MT5. برای توقف `Ctrl+C` بزنید. بعد از راه‌اندازی مجدد سیستم، همین دستور را اجرا کنید؛ سرویس خودکار دائمی نصب نشده است.

مسیرهای سفارشی:

```bash
./scripts/monitor_ramon.sh \
  --db /absolute/path/ramon_history.sqlite3 \
  --diagnostic /absolute/path/Ramon_Diagnostic.txt \
  --port 8013
```

فایل Diagnostic پیش‌فرض از پوشهٔ `Terminal/Common/Files` در Wine prefix `~/.mt5` پیدا می‌شود. اکسپرت باید `WriteDiagnosticFile=true` داشته باشد. فایل MAIN لازم است؛ فایل SMALL پذیرفته نمی‌شود. اگر MT5 در Docker یا Wine prefix دیگری است، فایل Common را از مسیر واقعی و قابل‌خواندن معرفی کنید. بعد از clone روی دستگاه دیگر، مسیر پیش‌فرض دوباره روی همان دستگاه کشف می‌شود.

## آنچه صفحه نمایش می‌دهد

- هر سه ثانیه دادهٔ موجود را بازخوانی می‌کند؛ cadence تصمیم‌گیری رامون را تغییر نمی‌دهد.
- انتخاب هر گره: وضعیت، شرط و مقادیر، زمان و منبع مشاهده را نشان می‌دهد.
- در نمایش باریک، نمای کلی متناسب با عرض است؛ دکمهٔ `＋` نمودار را برای خواندن بزرگ‌تر می‌کند و `−` به نمای کلی برمی‌گرداند.
- زمان‌ها در صفحه به وقت تهران و در API به UTC نمایش داده می‌شوند.
- دادهٔ مدل از `decision_samples`، نتیجهٔ معاملات از `trade_outcomes` و وضعیت اجرا از فایل MAIN Diagnostic می‌آید. نتیجهٔ سلامت فقط با `GET /health` بررسی می‌شود.
- انتخاب نمونهٔ مدل ابتدا با شناسهٔ دقیق Diagnostic انجام می‌شود. اگر آن نمونه پیدا نشود، آخرین نمونه نمایش داده می‌شود و ناهماهنگی شناسه هشدار دارد.

## معنی وضعیت‌ها

| وضعیت | معنی |
| --- | --- |
| شرط برقرار | مقدار ثبت‌شده شرط را برآورده می‌کند؛ به معنی اجرای تمام مراحل بعدی نیست |
| شرط ردشده | معیار مدل یا مانع صریح اکسپرت رد شده است |
| مشاهده‌شده | وضعیت یا پیش‌نمایش وجود دارد؛ نتیجهٔ عبور گیت ثبت نشده |
| نامشخص | مدرک لازم وجود ندارد؛ وضعیت حدس زده نمی‌شود |
| فقط ناظر | مدل نقش تحلیلی دارد و در حالت shadow تصمیم را تغییر نمی‌دهد |
| انتظار | در آخرین وضعیت مشاهده‌شده سفارش/پوزیشن فعال وجود ندارد |
| پوزیشن باز | فایل تازهٔ MAIN وجود پوزیشن را گزارش می‌کند |
| دادهٔ قدیمی | آخرین مشاهده وجود دارد، اما مدرک زنده نیست |

تازگی مدل از زمان دریافت نمونهٔ ذخیره‌شده با سقف ۹۰ ثانیه و تازگی اکسپرت از `Captured` فایل با سقف ۲۰ ثانیه سنجیده می‌شود. بازنویسی فایل، timestamp قیمت یا یک پاسخ تازهٔ `/health` زمان پیش‌بینی را تازه نمی‌کند. زمان بیش از پنج ثانیه در آینده خطای ساعت است. هنگام قطع ارتباط API، صفحه وضعیت گره‌ها را قدیمی می‌کند و تلاش مجدد دارد.

## محدودیت‌های واقعی

این نمودار وضعیت شرط‌ها را از telemetry موجود نمایش می‌دهد، نه اجرای ثانیه‌به‌ثانیهٔ درون شبکهٔ عصبی یا ردگیری تمام statementهای EA. اکسپرت با اولین مانع return می‌کند؛ گیت‌های بعدی ممکن است اصلاً اجرا نشده باشند. پیش‌نمایش RiskGate نیز مدرک تأیید نهایی مارجین یا ارسال سفارش نیست.

رد هر شرط رنج، تازگی tick به‌صورت عددی و خروجی همهٔ قفل‌ها برای هر تصمیم، در نسخهٔ فعلی کامل ثبت نشده‌اند. در این موارد «نامشخص» نمایش داده می‌شود. توسعهٔ بعدی برای trace کامل باید خروجی مشاهده‌ای هر گیت و timestamp را به همان `sample_key` وصل کند.

## استقلال از معاملات

سرویس مانیتور فقط روی loopback می‌شنود و SQLite را در حالت read-only و query-only باز می‌کند. مسیرهای نوشتن، باز/بسته‌کردن معامله، تغییر مدل و تغییر تنظیمات ندارد. به `/decision` یا `/trades` سرویس مدل درخواست نمی‌فرستد. بارگذاری صفحه هیچ تصمیم تازه‌ای تولید نمی‌کند.

## بررسی کد

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
node --check src/ramon/monitor_assets/app.js
```

ده آزمون مانیتور، مرز read-only، گیت نامشخص، پیش‌نمایش ریسک، دادهٔ قدیمی، ساعت آینده، شناسهٔ ناسازگار، فایل SMALL/نماد اشتباه، UTF-16 و سطح HTTP را بررسی می‌کنند. آزمون HTTP به شبکهٔ loopback نیاز دارد.
