# Risk policy audit — 2026-11-20

A code audit found that `RiskManager` treats an explicit 0.5% constructor argument as a legacy sentinel and reloads its file setting. If that file specifies a higher value, Django's capped configuration could therefore be overwritten. `_build_pipeline` now pins its computed ceiling after construction for both standard and demo paths. The change has not been deployed. The 49 targeted PostgreSQL-backed risk and replay tests pass. Independent execution engines, command authorization, portfolio exposure and live broker sizing require additional audit; this fix does not claim to cover them.

The running Django container reported `RAMON_DEMO_PROFIT_PROTECTION_ENABLED=1`, `RAMON_EA_COMMAND_CREATION_ENABLED=1`, and `RAMON_EA_COMMAND_EXECUTION_ENABLED=1`. In code all three are required before protection commands may be created, and account scope, account type, quote and position checks also apply. The setting being enabled does not prove a command was issued or filled. This is inconsistent with an assumption that demo breakeven is disabled. Do not change the runtime flag or restart the application without considering open positions, pending commands and the existing untracked deployment files. No existing stop was modified by this audit.
