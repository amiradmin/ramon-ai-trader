# رامون ۰٫۶۰: کنترل ریسک و آزمون سود خالص

این نسخه مبنای شش اقدام است. کاهش ریسک عملیاتی است؛ قواعد جدید ورود، خروج
و مدل‌ها ابزار آزمایش‌اند و تا وجود شاهد مستقل، به معاملات زنده اضافه نمی‌شوند.
هیچ نرخ درآمد یا جبران زیانی تضمین نشده است.

## تغییر عملیاتی

- معاملهٔ اصلی: استثنای حداقل حجم حداکثر ۱٫۲۵ برابر بودجهٔ مؤثر است، با
  حفظ سقف مطلق قبلی ۰٫۲۰ دلار. بودجهٔ مؤثر ۰٫۰۶ دلار یعنی سقف ۰٫۰۷۵ دلار.
  اگر مدل ریسک فعال شود، بودجهٔ مؤثر ممکن است با ضریب آن تغییر کند.
- لغزش مجاز ورود پیش از سفارش در سقف هر معامله و سقف مشترک حساب منظور
  می‌شود. توقف معاملهٔ کوچک نیز برای همین لغزش جا نگه می‌دارد.
- اگر ریسک واقعیِ حد ضرر یک معاملهٔ اصلی جدید از سقف ثبت‌شده عبور کند،
  درخواست خروج می‌دهد. سقف با شناسهٔ پوزیشن ذخیره و پس از شروع مجدد بازیابی
  می‌شود. پوزیشن‌های اصلی قدیمی برای این محافظ جدید به‌صورت خودکار بسته نمی‌شوند.
- شکاف قیمت، لغزش فراتر از مقدار مجاز، کارمزد و ردشدن خروج همچنان می‌تواند
  زیان واقعی را از سقف تخمینی بیشتر کند. حد ضرر تضمین قیمت نیست.
- هر دو نمودار باید نسخهٔ یکسان داشته باشند. هماهنگی ریسک تنها در همان
  نصب متاتریدر برقرار است. حفظ سود و سه مرحلهٔ خروج قبلی همچنان فعال‌اند.

## گزارش و آزمایش

۱. گزارش معمول، نتیجهٔ اصلی، کوچک و نقش نامشخص را جدا نشان می‌دهد؛ دلار
فقط با تبدیل واحدِ ثبت‌شده محاسبه می‌شود. نقش قدیمی از نسخهٔ فعلی حدس زده نمی‌شود.

۲. ابزار ارزیابی ورود، چند فرض ثابت را در ۷۰٪ قدیمی‌تر و ۳۰٪ جدیدتر جدا
می‌سنجد: تأیید هر دو جهت کوتاه‌مدت، هم‌جهتی بازده ۱۵/۶۰/۱۸۰ دقیقه، ورود بدون
استثنای حجم و فاصله از خبر با منبع معتبر. این بازده‌ها از کندل‌های پانزده‌دقیقه‌ای
هستند، نه مدل مستقل در سه تایم‌فریم. زیرمجموعهٔ معاملات انجام‌شده، نتیجهٔ
واقعیِ یک سیاست حذف ورود را ثابت نمی‌کند؛ حذف یک ورود می‌تواند ورود بعدی را عوض کند.

۳. مسیر سود و زیان پوزیشن در درخواست‌های موفق مدل ثبت می‌شود: با تنظیم
۳۰ ثانیه، نمونهٔ حدوداً سی‌ثانیه‌ای داریم، نه همهٔ تیک‌ها. ابزار خروج دو فرض
ثابت را با نتیجهٔ واقعی روی همان معاملات مقایسه می‌کند: فعال‌شدن قفل سود
در نیم واحد ریسک و خروج پس از پس‌دادن یک‌چهارم ریسک، و خروج با زیان نیم
ریسک بعد از دو دقیقه. مسیرهای ناقص و حجم‌های تغییرکرده حذف می‌شوند.
کارمزد ثبت‌شده و حاشیهٔ تخمینی هزینه لحاظ می‌شود؛ خروج فرضی قیمت اجرای واقعی نیست.

۴. ابزار مقایسهٔ مدل، مدل فعلی، یک مدل سازگار با رابط کرونوس و یک مبنای
مومنتوم را در بازهٔ زمانی یکسان و خارج از آموزش مقایسه می‌کند. مسیرها سفارش
نمی‌دهند و مدل فعال را تغییر نمی‌دهند. استفاده از مدل‌های با رابط دیگر به
آداپتور جدا نیاز دارد؛ این نسخه ادعای اجرای همهٔ مدل‌ها را ندارد.

۵. برای آزمون آینده، یک زمان شروع ثابت ثبت کنید و تنظیمات را تغییر ندهید.
نسخهٔ اکسپرت، تنظیمات واقعی نمودار، تنظیمات سرویس، نسخهٔ وزن مدل، بستهٔ نقش‌ها
و اثرانگشت کد در نمونه‌های ورود ذخیره می‌شوند. تغییر آنها آزمون ثبات را رد می‌کند.

۶. ابزار آمادگی حداقل ۱۰۰ معاملهٔ تازه و ۲۰ روز فعال، سود مثبت در هر دو
نیمه، ضریب سود حداقل ۱٫۲، نتیجهٔ مثبت هر نقش موردانتظار، هزینه و ساعت کامل،
رعایت سقف ثبت‌شده و افت بسته‌شدهٔ حداکثر ۱۰٪ سرمایهٔ مرجع را مطالبه می‌کند.
بازهٔ اطمینان تقریبی با بازنمونه‌گیری روزهای کامل، وابستگی درون روز را حفظ
می‌کند؛ وابستگی بین روزها و زیان پوزیشن باز در این آزمون پوشش کامل ندارد.
عبور از همهٔ شروط همچنان به بررسی مشخصات قرارداد حساب دلاری نیاز دارد.
هیچ حسابی خودکار فعال یا عوض نمی‌شود. پول لازم برای خرج خانه بودجهٔ این آزمایش نیست.

## دریافت و نصب روی دستگاه کاربر

```bash
cd ~/Documents/Presentation/ramon-ai-trader
git fetch origin feature/v060-profitability-validation
git switch feature/v060-profitability-validation
docker compose up -d --build model
bash scripts/setup_local.sh --mt5-only
```

کامپایل اکسپرت در متاادیتور و نمایش نسخهٔ **۰٫۶۰** روی هر دو نمودار را بررسی
کنید. ویژگی فایل در متاادیتور **۱٫۶۰۰** است؛ برچسب تشخیصی و معامله **۰٫۶۰**.
ورودی‌های ذخیره‌شدهٔ متاتریدر ممکن است باقی بمانند؛ آنها را در تشخیص بررسی کنید.
روی نمودار کوچک، آزمایش اسکالپ سریع را فقط اگر از قبل برای آزمایش انتخاب کرده‌اید
نگه دارید. این تغییر آن را خودکار روشن نمی‌کند.

وقتی هر دو نمودار آماده شدند، زمان ثابت شروع آزمون را بردارید:

```bash
date -u +%Y-%m-%dT%H:%M:%SZ
```

با همان مقدار ثابت، هر بار گزارش بگیرید؛ تاریخ را در اجراهای بعد عوض نکنید:

```bash
bash scripts/validate_profitability.sh 'زمان-ثابت-شروع-به-قالب-بالا'
bash scripts/analyze_ramon.sh --all
```

برای کار مستقیم روی کپی پایگاه داده:

```bash
uv run python -m ramon.profitability --db /path/to/copy.sqlite3 \
  --since-utc '2026-09-30T00:00:00Z' --version 0.60 --capital-usd 30
uv run python -m ramon.exit_research --db /path/to/copy.sqlite3 --buffer-r 0.05
```

تاریخ مثال را با زمان واقعی نصب عوض کنید. وضعیت ابتدا آماده نیست؛ داده‌های
نسخه‌های گذشته جای معاملات تازه را نمی‌گیرند. برای آزمون فقط یک نقش، گزینهٔ
`--roles MAIN` یا `--roles SMALL` وجود دارد و نتیجه فقط برای همان دامنه معتبر است.

مقایسهٔ مدل با اعداد زمانِ خام کندل متاتریدر، بازهٔ پیوستهٔ حداقل ۱۰۰ کندل
آزمون، ۲۵۶ کندل زمینه و اسپرد واقعی انجام می‌شود:

```bash
uv run --extra model python -m ramon.model_tournament \
  --db /path/to/copy.sqlite3 --challenger /path/to/checkpoint \
  --training-end-mt5 TRAINING_END --holdout-start-mt5 HOLDOUT_START \
  --holdout-end-mt5 HOLDOUT_END --cost-r ESTIMATED_COST_R
```

نام‌های بزرگ را با اعداد واقعی جایگزین کنید. هزینه شامل برآورد کارمزد و
لغزش اضافه است؛ اسپرد از قبل در شبیه‌سازی وجود دارد. تاریخ پایان آموزش
اظهار کاربر است و باید از سند آموزش مدل تأیید شود. این ابزار آن را از وزن
یک مدل خارجی استخراج نمی‌کند. اجرای وزن‌های واقعی به دستگاه و بسته‌های
مدل نیاز دارد؛ آزمون‌های خودکار از مدل‌های قطعی آزمایشی استفاده می‌کنند.
