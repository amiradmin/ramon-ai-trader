# محافظ دستی و مقایسه مدل‌ها — Ramon 0.59.5

دکمه «محافظ» کنار هر پوزیشن دستیِ زیان‌ده قرار دارد. کلیک فقط همان Ticket را برای حداکثر ۳۰ دقیقه مسلح می‌کند؛ «محافظ فعال · لغو» فرمان لغو می‌فرستد. وضعیت نمایش‌داده‌شده از تأیید EA می‌آید، نه صرفاً پاسخ HTTP. نسخه‌های قبلی EA این دکمه را فعال نمی‌کنند.

## رفتار محافظ

- SL اولیه باقی می‌ماند. مدل باید پس از مسلح‌سازی، دو snapshot متمایز و تازه با جهت مخالف بدهد؛ Intrabar و AI Trend نیز باید همان جهت را تأیید کنند. زیان به‌تنهایی باعث ورود نمی‌شود.
- ابتدا هزینه، اسپرد، حجم، مارجین، مجوز حساب، خبر و cooldown بررسی می‌شوند. اگر ورود مخالف در سقف ریسک نگنجد، محافظ منتظر می‌ماند و دلیل در وضعیت EA ثبت می‌شود.
- بعد از تأیید، پوزیشن اصلی **کاملاً بسته می‌شود**؛ سپس شرایط دوباره بررسی شده و فقط یک سفارش مخالف ممکن است ارسال شود. پوزیشن مخالف هم‌زمان برای قفل کردن ضرر باز نمی‌شود. بعد از خروج، رد شدن سفارش دوم یا توقف برنامه، ورود جبرانی تکرار نمی‌شود.
- ریسک اسمی SL ورود جدید حداکثر `min(GuardianMaxRiskUSD, MaxExecutableRiskUSD)` است؛ پیش‌فرض `GuardianMaxRiskUSD=0.06` دلار واقعی است، نه ۶ دلار یا ۶ واحد حساب. حجم از حجم اولیه بیشتر نمی‌شود و برای حداقل لات هیچ استثنایی وجود ندارد. حداقل لاتِ بیش از بودجه باعث انتظار می‌شود.
- این سقف **ریسک اضافی ورود جدید** است؛ ضرر قطعی‌شده پوزیشن قبلی نیز باید در نتیجه کلی حساب شود. کمیسیون، سواپ و لغزش اجرا می‌توانند زیان واقعی را بیشتر کنند. هیچ تضمین جبران ضرر وجود ندارد.
- ورود محافظ SL/TP واقعی نزد بروکر دارد و حداکثر ۱۵ دقیقه نگه داشته می‌شود؛ قطعی ترمینال اجرای خروج زمانی را به تأخیر می‌اندازد، ولی SL/TP نزد بروکر باقی می‌ماند. ورود محافظ دوباره قابل مسلح شدن نیست؛ افزایش پله‌ای حجم وجود ندارد.
- وضعیت یک‌بارمصرف در Global Variables حساب/سرور ذخیره می‌شود. رخدادهای محافظ با برچسب‌های `guardian_original_close`، `guardian_recovery_entry` و `guardian_timeout_exit` ثبت می‌شوند. ورود جدید به ردیف انسانی اولیه متصل است و شناسه اجرای جدا دارد.

## پیشنهادهای مدل‌ها

در بخش پیشنهاد Ramon، V2 و V3 همراه Chronos، TimesFM و Kronos-small نمایش داده می‌شوند:

- Chronos و TimesFM از forecast همان snapshot ذخیره‌شده ردیف می‌آیند؛ با رأی نهایی موتور معاملاتی فرق دارند. محدوده خنثی نصف اسپرد همان snapshot است.
- Kronos یک worker جدا دارد و از OHLC کامل M15 استفاده می‌کند؛ برای هر کندل کامل یک forecast واقعی با افق پیش‌فرض ۴ کندل تولید می‌کند. پیش‌فرض محدوده خنثی `0.42` واحد قیمت است و باید با اسپرد واقعی تنظیم شود.
- Kronos فقط برای کندل کامل فعلی و ردیف همان کندل نشان داده می‌شود؛ **یک پیش‌بینی جاری** است، نه ادعای پیش‌بینی ثبت‌شده در زمان کلیک تاریخی. زمان و افق در tooltip مشخص‌اند. تاریخچه‌ قدیمی، داده آینده، خروجی benchmark آفلاین یا مدل آماده‌نشده به BUY/SELL تبدیل نمی‌شود.
- این پیش‌بینی‌ها درصد اطمینان ندارند و فقط برای مقایسه دستی‌اند؛ هیچ تغییری در V2/V3 یا سیاست ورود/محافظ ایجاد نمی‌کنند. TimesFM هم فقط وقتی خروجی واقعاً آماده باشد نمایش داده می‌شود.

## به‌روزرسانی

در مسیر پروژه، تغییرهای محلی خود را ابتدا بررسی کن:

```bash
git status --short
git pull --ff-only origin main
docker compose build model dashboard
docker compose up -d model dashboard
```

فایل `mt5/Ramon.mq5` را در مسیر Ramon نصب‌شده کپی کن و در MetaEditor با F7 کامپایل کن؛ سپس EA جدید را روی چارت بارگذاری کن. نسخه باید `0.59.5` باشد. این محیط MetaEditor ندارد؛ کامپایل و سناریوهای اجرای بروکر اینجا تأیید نشده‌اند. محافظ را پیش از استفاده واقعی روی حساب دمو بررسی کن: لغو، سیگنال مخالف، رد سفارش، restart و حداقل لات بیش از بودجه.

Kronos به‌طور پیش‌فرض اجرا نمی‌شود. برای دریافت پیشنهاد واقعی آن، پس از ساخت image اصلی:

```bash
docker compose --profile advisors build kronos-advisor
docker compose --profile advisors up -d kronos-advisor
docker compose logs -f kronos-advisor
```

این سرویس checkpoint رسمی `NeoQuasar/Kronos-small` و tokenizer آن را دانلود می‌کند. CPU روی دو هسته و حافظه کانتینر روی ۲ گیگابایت محدود است. هنگام بارگذاری یا نبود تاریخچه کافی، جدول «در دسترس نیست» نشان می‌دهد. به پایگاه داده واقعی `XAUUSD_l` نیاز دارد؛ benchmark Kaggle خروجی زنده نیست. Docker build و دانلود وزن‌ها در این محیط اجرا نشده‌اند.

منابع اصلی: [Kronos](https://github.com/shiyu-coder/Kronos)، [checkpoint](https://huggingface.co/NeoQuasar/Kronos-small)، [XGBoost](https://github.com/dmlc/xgboost)، [Qlib](https://github.com/microsoft/qlib). XGBoost و Qlib گزینه‌های تحقیق برای آموزش خروج هستند و در این تغییر فعال نشده‌اند.

اعتبارسنجی این تغییر: ۷۷ تست مربوط به محافظ، پیشنهادها، monitor، فرصت‌ها، کنترل و تنظیمات محلی پاس شد؛ JavaScript نیز از نظر syntax بررسی شد. ۲۶ شکست در تست‌های قدیمی source-contract قبل از تغییر هم وجود داشت و مربوط به نسخه‌ها و قراردادهای قدیمی است. این تست‌ها سودآوری، اجرای واقعی بروکر یا کامپایل MQL5 را تأیید نمی‌کنند.

## یادآور رفتاری ترید

### زمان ورودی Kronos

زمان کندل‌های ورودی EA ساعت بروکر است. Kronos از آخرین `inference_audit` و `input_blobs`، دادهٔ دقیق همان درخواست را می‌خواند و با `broker_utc_offset_seconds` ثبت‌شده به UTC تبدیل می‌کند. اختلاف ساعت از روی ساعت امروز یا فاصلهٔ دلخواه حدس زده نمی‌شود. درخواست قدیمی، اختلاف ساعت نامعلوم یا ساعت قیمت ناسازگار، خروجی نامعتبر تولید می‌کند. گزارش جدید هم زمان UTC و هم شناسهٔ کندل اصلی بروکر را دارد تا جدول همان کندل را تطبیق دهد. داده‌های قبلی پایگاه داده و منطق اجرای EA تغییر نمی‌کنند.

برای اجرای خودکار کانتینرها پس از روشن شدن اوبونتو، [راهنمای راه‌اندازی](ubuntu-startup.md) را ببین.

کادر قدیمی راهنمای ۳۰ دقیقه‌ای Chronos با یادآور رفتاری جایگزین شد. از پوزیشن‌های دستی تازه و حداکثر ۸ معامله بسته‌شده موجود در snapshot، مواردی مانند دو ضرر، دو برد، چند معامله بسته‌شده در ۱۵ دقیقه، ضرر باز و محافظ فعال بررسی می‌شوند. اطلاعات قدیمی، معامله خودکار، timestamp با منطقه زمانی نامعلوم و داده آینده برای ادعای «معامله دستی اخیر» استفاده نمی‌شوند. اطلاعات ناکافی فقط پیام عمومی تولید می‌کند؛ این بخش احساسات کاربر را تشخیص نمی‌دهد و هیچ سفارشی نمی‌فرستد.

قواعد در مرورگر اجرا می‌شوند؛ مدل زبانی، GPU، دانلود وزن یا درخواست شبکه جدید ندارند. polling مربوط به ChronosSlope در این کادر حذف شده؛ پیش‌بینی‌های سایر قسمت‌های جدول باقی هستند. ۶ تست رفتاری Node و ۳۶ تست monitor پاس شدند؛ مسیر HTTP فایل و رفتار DOM نیز بررسی شدند. پس از دریافت تغییر، فقط ساخت و restart سرویس `dashboard` کافی است و این تغییر جدید به کامپایل مجدد EA نیاز ندارد.
